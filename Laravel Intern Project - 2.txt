Laravel Intern Project - 2
University & College Course Management System API
Project Overview
Build an API-only University & College Course Management System using Laravel.
The system should allow a university or college to manage:
* Faculties
* Departments
* Academic programs
* Courses
* Course prerequisites
* Academic semesters
* Students
* Lecturers
* Course offerings
* Class enrollments
* Class schedules
* Attendance
* Assignments
* Assignment submissions
* Exams
* Grades
* Announcements
There will be no frontend.
The application must expose REST APIs that could later be consumed by a web application, mobile application, or student portal.

2. Authentication
Implement API authentication.
Users should be able to log in using:
POST /api/login
Use Laravel Sanctum.
The following types of users should exist:
* Administrator
* Lecturer
* Student
Users should only be able to access functionality they are authorized to use.
Example:
A student must not be able to create a course.
A lecturer must not be able to modify another lecturer's course unless authorized.

8. Course Prerequisites
Courses may have prerequisites.
Example:
CS201 – Data Structures
requires
CS101 – Introduction to Programming
A course may have multiple prerequisites.
The system must prevent invalid prerequisite relationships.
Examples:
A course cannot be its own prerequisite.
Circular prerequisite relationships should not be allowed.
Example:
CS101 → CS201
CS201 → CS101
should not be possible.

10. Course Offerings
A course is the permanent academic definition.
A course offering represents that course being taught during a particular semester.
Example:
Course:
CS101 – Introduction to Programming
Course Offering:
CS101
Semester 1 – 2026
Lecturer: Ahmed
Capacity: 40
The same course may therefore have multiple offerings over time.
Course offerings should support:
* Course
* Semester
* Lecturer
* Maximum number of students
* Enrollment status
* Start/end dates if required
________________


11. Lecturer Assignment
Administrators should assign lecturers to course offerings.
A lecturer should be able to retrieve:
GET /api/lecturer/course-offerings
and see only the courses assigned to them.
Lecturers should not be able to modify course offerings assigned to other lecturers.
Use proper Laravel authorization.

* Status
Possible status:

13. Course Registration / Enrollment
Students should be able to enroll in course offerings.
Example:
POST /api/course-offerings/{id}/enroll
Before enrollment, validate:
* Registration period is open
* Student is active
* Course offering has available capacity
* Student is not already enrolled
* Required prerequisites have been completed
* Student is allowed to take the course
* Course offering belongs to an active/upcoming semester
The enrollment should not simply insert a database row.
Implement proper business logic.
________________


14. Enrollment Capacity
A course offering may have:
maximum_students = 30
If 30 students have already enrolled, student number 31 should not be allowed to enroll.
The implementation should also consider multiple simultaneous enrollment requests.
Avoid allowing the capacity to be exceeded because of a race condition.
________________


15. Course Withdrawal
Students should be able to withdraw from a course.
Example:
DELETE /api/enrollments/{id}
Withdrawal should only be allowed before a configured withdrawal deadline.
Store the enrollment status instead of necessarily deleting historical records.
Possible statuses:
* enrolled
* withdrawn
* completed
* failed
________________


16. Class Schedule
A course offering can contain multiple scheduled classes.
Example:
CS101
Sunday
09:00 – 11:00
Room A201
Tuesday
09:00 – 11:00
Room A201
Schedule information should contain:
* Day/date
* Start time
* End time
* Room/location
* Course offering
Prevent obvious schedule problems.
For example:
A lecturer should not be assigned to two classes occurring at the same time.
A classroom should not be allocated to two classes at the same time.

Possible statuses:

Students should be able to view their own attendance.

24. Final Course Grades
Calculate a student's final course score using weighted assessments.
Example:
Assignments = 30%
Midterm = 20%
Final Exam = 50%
Total:
assignment_score × 0.30
+ midterm_score × 0.20
+ final_exam_score × 0.50
Convert the resulting score into grades.
Example:
90–100 = A
80–89 = B
70–79 = C
60–69 = D
Below 60 = F
Do not hardcode the calculation directly inside a controller.
Design the application so grading rules can be maintained properly.
________________

37. Database Transactions
Use database transactions for operations involving multiple related changes.
Course enrollment is one example.
A transaction may need to:
1. Verify capacity.
2. Create enrollment.
3. Update related information.
4. Dispatch relevant application logic.
Failure should not leave the database in an inconsistent state.

Important Rule
This project is not a CRUD exercise.
The purpose is to demonstrate that you understand how to build a real Laravel application with business rules.
For example, implementing:
POST /course-offerings/{course}/enroll
as:
Enrollment::create([
    'student_id' => auth()->id(),
    'course_offering_id' => $course->id
]);


is not sufficient.
You must handle:
* Authorization
* Course capacity
* Duplicate enrollment
* Semester status
* Registration dates
* Student status
* Prerequisites
* Transactions
* Race conditions
* Notifications
The quality of these business rules will be an important part of the assessment.
